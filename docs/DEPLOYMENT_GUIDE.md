# 🚀 AURUMCHAIN Deployment Guide

This guide provides a step-by-step walkthrough for deploying the AURUMCHAIN ecosystem, including the Solana Smart Contracts, Supabase Backend, and Frontend Application.

---

## 📋 Prerequisites

1.  **Solana Wallet**: Install [Phantom](https://phantom.app/).
    - **Enable Dev Mode**: Open Phantom -> Settings -> Developer Settings -> Enable **"Testnet Mode"** (or Developer Mode).
    - **Switch to Devnet**: Ensure your wallet is set to **Solana Devnet**.
2.  **Solana Playground**: Access to [beta.solpg.io](https://beta.solpg.io/).
    - **Connect Wallet**: Click the "Disconnected" status in the bottom-left of Solana PG and select **"Phantom"** (do not use the burner wallet).
3.  **Solana Faucet**: You will need test SOL.
    - Visit [faucet.solana.com](https://faucet.solana.com/).
    - Connect your GitHub for verification to get up to **10 SOL** per 8 hours.
4.  **Supabase Account**: Create a project at [supabase.com](https://supabase.com/).
5.  **GitHub Repository**: Ensure you have access to the AURUMCHAIN codebase.
6.  **Node.js**: Version 18 or higher installed.
7.  **Solana CLI**: Required for creating custom tokens and advanced wallet management.
    - **Linux / macOS**:
      ```bash
      sh -c "$(curl -sSfL https://release.solana.com/stable/install)"
      ```
    - **Windows (PowerShell)**:
      ```powershell
      cmd /c "curl https://release.solana.com/v1.18.15/solana-install-init-x86_64-pc-windows-msvc.exe --output C:\solana-install-init.exe --remote-name"
      C:\solana-install-init.exe v1.18.15
      ```

## 🛠️ Phase 1: Solana Program Deployment (Solana Playground)

You need to deploy three programs. Repeat these steps for each:

- `project_registry`
- `compliance_transfer`
- `allocation_distribution`

### Step 1: Load Program into Playground

1.  Open [Solana Playground](https://beta.solpg.io/).
2.  Create a new project (select "Anchor").
3.  Copy the contents of `programs/<program_name>/src/lib.rs` into the Playground's `lib.rs`.
4.  Copy other files from the same program's `src/` directory (like `state.rs`, `logic.rs`) into the Playground project structure. Playground allows creating folders and files.

### Step 2: Build and Get Program ID

1.  Click the **"Build"** button (hammer icon) in the left sidebar.
2.  Once built, go to the **"Deploy"** tab.
3.  You will see a **Program ID** generated by Playground. **Copy this ID.**

### Step 3: Synchronize Program ID

1.  In Playground, find the line `declare_id!("...");` at the top of `lib.rs`.
2.  Replace the old ID with the **new Program ID** you just copied from the Deploy tab.
3.  Click **"Build"** again.
4.  Click **"Deploy"**.

**IMPORTANT**: The wallet you use to deploy these programs will automatically become the **Super Admin** authority for the smart contracts. Ensure you have the private key of this wallet saved (as `WALLET_PRIVATE_KEY` in `.env`).

### Step 4: Repeat for All Programs

Do this for all three programs and keep a record of the three new Program IDs.

## 🗄️ Phase 2: Supabase Backend Setup

### Step 1: Run Migrations

1.  Go to your [Supabase Dashboard](https://supabase.com/dashboard).
2.  Select your project -> **SQL Editor**.
3.  Open the files in `supabase/migrations/` one by one (starting from `001_...` to `013_...` and finally `sync_redeploy.sql`).
4.  Copy the content of each file into the SQL Editor and click **"Run"**.

### Step 2: Assign Super Admin

After the migrations are done and you have registered your first user (see Phase 4), you need to grant them Super Admin privileges:

1.  In the Supabase SQL Editor, run this query to find your user ID:
    ```sql
    SELECT id, email FROM auth.users;
    ```
2.  Copy the `id` (UUID) for your admin user.
3.  Run the following query to grant the role (replace `YOUR_USER_UUID`):
    ```sql
    INSERT INTO public.user_roles (user_id, role)
    VALUES ('YOUR_USER_UUID', 'super_admin');
    ```

## ⚙️ Phase 3: Codebase Configuration

Now you must update the codebase with your new Program IDs and Supabase credentials.

### Step 1: Update Environment Variables

Create a `.env` file in the root directory. You can copy the structure from `.env.example`:

```env
# ===========================================
# ADMINISTRATIVE & PRIVATE KEYS
# ===========================================
WALLET_PRIVATE_KEY=your_base58_private_key_here # Deployer Wallet Private Key

# ===========================================
# SUPABASE CONFIGURATION
# ===========================================
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key # Required for CLI scripts

# ===========================================
# BLOCKCHAIN CONFIGURATION (Solana)
# ===========================================
NEXT_PUBLIC_SOLANA_RPC_URL=https://api.devnet.solana.com
NEXT_PUBLIC_PROJECT_REGISTRY_PROGRAM_ID=your_new_id
NEXT_PUBLIC_COMPLIANCE_PROGRAM_ID=your_new_id
NEXT_PUBLIC_ALLOCATION_DISTRIBUTION_PROGRAM_ID=your_new_id

# Stablecoin Mint (Mock USDC)
NEXT_PUBLIC_USDC_MINT=AJujcxZiQ1jUvSixiFLQNWFCpUtMuVsbyPCQ8ByU3jvf
```

### Handling Mock USDC

To test investments, you need a stablecoin mint address. The commands below work on **both Windows (PowerShell/CMD) and Linux/macOS**.

- **Option A (Default)**: Use the provided mock USDC (`AJujcxZiQ1jUvSixiFLQNWFCpUtMuVsbyPCQ8ByU3jvf`).
  > [!TIP]
  > **Note to Client**: Please share your Solana Devnet wallet address with us. We will send the initial SOL and Mock USDC balance to your target wallet so you can start testing immediately.
- **Option B (Custom)**: Create your own mock USDC using the Solana CLI:

  ```bash
  # 1. Set your CLI to devnet
  solana config set --url https://api.devnet.solana.com

  # 2. Create the token mint (6 decimals for USDC standard)
  spl-token create-token --decimals 6

  # 3. Create your account for this token
  spl-token create-account <MINT_ADDRESS_FROM_STEP_2>

  # 4. Mint tokens to yourself (e.g., 1,000,000 tokens)
  spl-token mint <MINT_ADDRESS_FROM_STEP_2> 1000000
  ```

  _Ensure this new Mint Address is updated in your `.env` as `NEXT_PUBLIC_USDC_MINT`._

### Step 2: Update Program IDs & IDLs

You must update the IDs and IDLs in these locations:

1.  **Program IDs**:
    - `Anchor.toml`: Update IDs under `[programs.devnet]`.
    - `lib/web3/config/programs.ts`: Update the fallback strings.
    - `programs/<name>/src/lib.rs`: Update the `declare_id!` macro.

2.  **IDL Synchronization**:
    - After deploying in Solana PG, click the **"Export IDL"** (JSON) option in the Deploy tab.
    - Save each JSON file into `programs/<program_name>/src/idl.json`.
    - Run the following command in your terminal to sync them to the frontend:
      ```bash
      npm run sync-idl
      ```

## 👤 Phase 4: CLI-Based User Management & KYC

Since the frontend registration and KYC UI are currently in development, all users (both Investors and Admins) must be managed via the CLI scripts and the Supabase Dashboard.

### Step 1: Create a User (Common for all)

1.  Go to your **Supabase Dashboard** -> **Authentication** -> **Users**.
2.  Click **"Add user"** -> **"Create new user"**.
3.  Enter an email and password for the person (Investor or Admin).

### Step 2: Verify a Regular User (Investor)

Any user who wants to participate in investments or receive tokens must be "Verified" on-chain and in the database.

1.  Ask the user for their **Solana Wallet Address**.
2.  Run the `manual-verify.ts` script:

    ```bash
    npx tsx scripts/manual-verify.ts <user_email> <solana_wallet_address>
    ```

    _This links their wallet, approves their KYC status in Supabase, and records their eligibility on the Solana blockchain._

3.  **Fund the Investor Wallet**:
    To allow the investor to perform transactions and invest, the Admin must send them funds:
    - **SOL**: Transfer at least **1 test SOL** (for gas fees).
    - **Mock USDC**: Transfer a sufficient amount of Mock USDC (e.g., 50,000) for them to use in investment testing.

    _You can use the Phantom wallet or the `spl-token transfer` command to send these funds._

### Step 3: Promote to Super Admin (Client Only)

Only the client or specific administrators should be promoted to `super_admin`. This role allows access to the Admin Dashboard (once active) and the ability to finalize projects and payouts.

1.  First, ensure the user is created (Step 1).
2.  In the **Supabase SQL Editor**, run:

    ```sql
    -- Find the user ID for the person you want to make Admin
    SELECT id, email FROM profiles WHERE email = 'admin@example.com';

    -- Grant the super_admin role (Replace YOUR_USER_ID)
    INSERT INTO public.user_roles (user_id, role)
    VALUES ('YOUR_USER_ID', 'super_admin');
    ```

## 🚀 Phase 6: Project Walkthrough & Lifecycle

This section explains how to use the platform once the deployment is complete.

### 🛡️ 1. The Admin Workflow (Operator)

#### A. Project Creation

- **Page Link**: `http://localhost:3000/admin/projects`
- **Action**: Click "Create New Project".
- **Logic**: When you create a project, the system atomically:
  1.  Creates a new **SPL Token Mint** on Solana.
  2.  Registers **Metaplex Metadata** (Name, Symbol, Logo).
  3.  **Revokes Admin Authority**: The Mint Authority is transferred to the Smart Contract (PDA). This ensures that only the program can mint tokens (Zero-Trust).

#### B. Managing Project Phases

Projects move through a strict lifecycle:

- **Draft**: Initial setup.
- **Funding**: Open for investor subscriptions.
- **Active**: Funding goal met; project is operational. Lock-up period usually starts here.
- **Completed**: Project finished; final distributions made.

#### C. Compliance & Verification

- **Page Link**: `http://localhost:3000/admin/compliance`
- **Action**: Approve or Reject investor KYC requests.
- **Logic**: No user can invest until they are "Approved" in this dashboard. This is enforced by the `compliance_transfer` smart contract.

#### D. Executing Payouts (Dividends)

- **Page Link**: `http://localhost:3000/admin/distributions`
- **Action**: Create a new "Epoch" and execute payouts.
- **Logic**: The system scans the blockchain to find every current holder of the project's tokens and distributes USDC directly to their wallets based on their ownership percentage.

---

### 💰 2. The Investor Workflow

#### A. Browsing & Investing

- **Page Link**: `http://localhost:3000/projects`
- **Action**: Select a project in the "Funding" phase and click "Invest".
- **Logic**: The investor commits USDC. The status moves from `Pending` -> `Settled` (payment confirmed) -> `Allocated` (tokens minted and delivered).

#### B. Direct-to-Wallet Delivery

- Unlike traditional platforms, tokens are delivered **directly to the investor's Phantom wallet**.
- **The Lock-up**: Tokens are "Frozen" in the investor's wallet by the smart contract until the project's lock-up date expires, preventing premature secondary market selling.

#### C. Portfolio Tracking

- **Page Link**: `http://localhost:3000/dashboard`
- **Action**: View total investments, held tokens, and received payouts.
